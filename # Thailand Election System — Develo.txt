# Thailand Election System — Development Plan

## Context
Building a dual-purpose national election platform from the PRD v4.0:
- **Election Reporting System** — real-time public results across 77 provinces
- **Online Voting System** — authenticated digital ballot casting

This is a portfolio project. The following are **mocked/simplified**:
- DOPA API (Thai national ID verification) → local mock service
- OTP SMS delivery (Twilio/SNS) → log-only in dev, mock endpoint
- Distributed Ed25519 PKI for polling stations → single test key pair
- Vault/AWS Secrets Manager → `.env` file

**Full implementations kept:** JWT auth flow, PostgreSQL schema, Redis 3-instance design, Kafka workers, Centrifugo WebSocket, Circuit Breaker, asynq background jobs, Kong API Gateway.

## Phase 4 — Kafka Workers & Vote Ingestion

**Goal:** Physical votes POST → Kafka → Worker → DB + Redis + Centrifugo broadcast.

### 4.1 Physical Vote Ingestion (B-01)
- `internal/api/handlers/ingestion.go` — `POST /api/v1/votes`
  - Validate API Key (from Kong, but also app-level check)
  - Verify Ed25519 payload signature against `province_keys` table
  - Idempotency check: `SET idempotency:<key> NX EX 86400` on redis-persistent
  - Publish to Kafka topic by ballot_type
  - Return 202 in < 10ms

### 4.2 Kafka Setup
- `internal/kafka/producer.go` — `confluent-kafka-go` or `segmentio/kafka-go` producer
- Redpanda in Docker Compose (Kafka-compatible, no Zookeeper)
- 4 topics: `votes.constituency`, `votes.party_list`, `votes.referendum`, `votes.online`

### 4.3 Worker (W-01 through W-07)
- `cmd/worker/main.go` — starts 4 Kafka consumers + asynq server
- `internal/worker/constituency_consumer.go` — consumes `votes.constituency`
- `internal/worker/party_list_consumer.go`
- `internal/worker/referendum_consumer.go`
- `internal/worker/online_consumer.go`
- Each consumer: `BEGIN TX → INSERT vote_events → UPSERT summary → COMMIT → update Redis ZSETs → Centrifugo publish`
- `internal/realtime/centrifugo.go` — `gocent` client wrapper for broadcasting

### 4.4 asynq Scheduled Jobs (W-08 through W-13)
- `internal/worker/scheduler.go` — register all 4 scheduled tasks
- `reconciliation_handler.go` — compare Redis ZSETs vs PostgreSQL SUM, alert on drift > 0.01%
- `party_list_calculator.go` — recalculate 100-seat proportional allocation (PRD §1.3.3)
- `session_cleanup_handler.go` — expire stale voter_sessions
- `audit_export_handler.go` — daily export stub (logs to stdout for portfolio)

## Phase 5 — Online Voting Backend

**Goal:** Complete voter auth flow (mocked DOPA + mock SMS) + atomic vote casting.

### 5.1 Auth Flow Handlers (B-12 through B-14)
`internal/api/handlers/online_voting.go`:
- `POST /online-voting/auth/verify-id`
  - Hash national_id with SHA-256 + pepper → look up `voter_registry`
  - Call DOPA mock (HTTP to `dopa-mock` service)
  - Check all ballots already cast → return status
- `POST /online-voting/auth/request-otp`
  - Generate 6-digit OTP → store hash in redis-persistent (TTL 5 min)
  - Enqueue `voter:otp:send` asynq task (mock: just log OTP to console in dev)
  - Return 202 with expires_in_seconds
- `POST /online-voting/auth/verify-otp`
  - Constant-time compare hashed OTP
  - Delete OTP from Redis (one-time use)
  - Create `voter_sessions` record
  - Issue anonymous JWT RS256 (contains ONLY: anonymous_vote_token, expiry, eligible_ballots — NO national_id)

### 5.2 Voting Handlers (B-15 through B-18)
- `GET /online-voting/eligibility` — which ballots remain for this session
- `GET /online-voting/ballot/:ballot_type` — return candidates/parties for voter's constituency
- `POST /online-voting/cast` — the critical atomic operation:
  1. Acquire distributed lock: `SET vote_lock:{voter_session_id} NX EX 10`
  2. `SELECT FOR UPDATE` on voter_rights_used
  3. INSERT vote_events (anonymous_token, NO national_id)
  4. INSERT voter_rights_used (session_id, ballot_type — NO vote choice)
  5. COMMIT → release lock
  6. Enqueue to `votes.online` Kafka topic
  7. Enqueue `voter:receipt:issue` asynq task
  8. Return 202 + receipt_id
- `GET /online-voting/receipt/:receipt_id` — public receipt verification (no auth)

### 5.3 JWT Middleware
- `internal/api/middleware/jwt.go` — RS256 JWT validation for voter + admin routes
- Private key: generated once, stored in `.env` (portfolio simplification)
- Anonymous JWT payload: `{ "avt": "<uuid>", "exp": ..., "ballots": [...] }`

### 5.4 asynq Task Handlers (Online Voting)
- `voter:otp:send` → in dev: log "OTP for session X: 123456" to stdout
- `voter:receipt:issue` → SHA-256(anonymous_token + choice_id + timestamp) → INSERT vote_receipts
